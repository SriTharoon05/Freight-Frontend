# Freight Partners mobile app

Partners sign in with Google using PKCE through the system browser. Configure the central Supabase Google provider and allow the exact callback `freightpartners://app`; phone numbers are contact details. No SMS or email login message is required. Use only the dedicated partner project's public URL/key in this build.

Transport agents accept tasks and assign drivers by name, **Google account email**, international contact phone number and optional vehicle. **Share driver link on WhatsApp** opens a prefilled message; automatic sending is optional when the central service has an approved Meta template and the driver's consent. Drivers sign in with the assigned Google account and record progress, actual event time, proofs, recipient and GPS at the task-specific browser link, without installing the app. The API checks the verified provider email; forwarded links alone do not grant access. Reassigning/renewing a driver revokes the previous link. Agent phones do not supply GPS for delegated drivers. See the backend's `partner_network/README.md` for migration `network_0005`, HTTPS hosting, Google and WhatsApp setup.

Browser GPS requires location permission and an active page; backgrounding, locking the phone and losing connectivity can interrupt it. Actual milestone time and system recording time are shown separately in all timelines. Shipper/consignee email alerts are sent by the company worker, using job contact email addresses. Real phone/browser and provider delivery checks remain required before release.

React Native/TypeScript with Expo development builds for Android and iPhone. Install dependencies with `npm ci` and copy `.env.example` to `.env`. Use the central network service's public Supabase configuration. Company staff credentials and company database credentials never belong in this app.

The owner's free pilot API is deployed at `https://freight-partners-api.onrender.com` against the separate partner Supabase project. Copy `.env.pilot.example` to `.env` to use its public connection settings. FGL activation and the signed connection in both directions were verified on 26 October 2026; native signing/Firebase configuration and physical-device checks remain pending. The Meridian demo uses fictional data.

The mobile app also has a browser build at `https://freight-partners-api.onrender.com/v1/partners/`, separate from the staff website. Google PKCE sign-in returns through the existing `/v1/driver` callback on the same origin, with separate driver/owner/web session namespaces. The web build uses the same task, driver-assignment, warehouse and Inbox screens. First-time Google users must save their partner profile before accessing those tabs. The owner's test-account sign-in round trip was verified; unrestricted public Google access is not established by that test.

Run `npm run build:web` to export `dist/`. To update the free API's public website build, run `node scripts/build-web.mjs --backend <absolute-backend-checkout>` and review/push the resulting `partner_network/web-build/` changes. The script validates the destination before replacing generated output. It does not change either company's database. Staff login links to this separate website.

The browser keeps authentication in session storage and pending work/proof in IndexedDB encrypted with a non-extractable AES-GCM key; this is not the native SQLCipher/keychain and does not protect against script access on the same origin. Uploads precede completion events, and unsent work prevents sign-out. Browser storage must remain enabled. Inbox refresh runs while the app is active; browser push is not configured. Browser GPS requires permission and a visible page, and stops when the page is hidden. Native background location and native Firebase remain separate capabilities.

The 29 October browser redesign adds a responsive sign-in page, desktop sidebar and phone navigation, actual assignment counts, searchable job cards, a visible unread Inbox, profile onboarding and a clearer driver form. The shared `src/workspace.ts` hook retains the native and browser session/synchronisation flow. Browser-only components and CSS are in `App.web.tsx`, `src/ui.web.tsx`, `src/web-ui.tsx` and `src/web.css`. The [Dribbble courier dashboard reference](https://dribbble.com/shots/26885219-Courier-Driver-App-Task-Management-Tracking-UI) informed the card hierarchy and mobile navigation; its images and artwork are not included in the app. Visual workflow testing uses a separate local fixture with fictional Meridian data, excluded from the production export.

Place matching Firebase `google-services.json` and `GoogleService-Info.plist` files under ignored `secrets/` paths and configure their environment paths. Enable Firebase Cloud Messaging/APNs, register these bundle IDs, and provide Android/iOS signing credentials through your build service. If your organisation uses different bundle IDs, edit `app.config.ts` before registering Firebase applications. Expo SQLCipher and native Firebase require development builds; **Expo Go is unsupported**.

Run `npm run android` with Android Studio/SDK installed, or `npm run ios` on a Mac with Xcode. EAS build profiles are supplied for development, preview and production; configure your EAS project/account before using them. Run `npm run typecheck`, `npm test`, and `npx expo config --type public` for local checks. Do not publish until the backend's `partner_network/RELEASE_CHECKLIST.md` passes on physical devices.

The app supports Google registration, multiple capabilities, discovery opt-in, company relationships, multi-company work, revised-brief acknowledgement, progress, private documents, photos/PDF proof, handover/clearance details, warehouse listings, quotations, confirmation, receipt/dispatch and a durable inbox. Administrators whose Supabase UUIDs are centrally allowlisted can verify partner profiles from the Admin tab.

Offline briefs, captured proof bytes, events and GPS samples live in encrypted SQLCipher. Secure-store keys use access after first unlock so background callbacks can work while the screen is locked. Uploads precede queued completion; errors caused by new instructions or closed tasks remain visible for review. Never discard pending proof merely to sign out. Transport tracking stops immediately on local completion submission and reconciles cancellation/reassignment when online. Background execution depends on permission, battery management and OS/app lifecycle; do not promise continuous tracking after force termination.

Google verifies the sign-in email. Warehouse owners must also pass network verification before discovery/quotations. Acceptance and reservation confirmation require a live connection. Quotes do not reserve capacity; the central server atomically confirms a selected offer across all freight companies.

No production keys or native credential files are checked in. Compatible gRPC and UUID overrides remove their known advisories. The current npm audit still reports 17 high-severity upstream transitive build-tool advisories in braces and node-forge; compatible fixes must be reviewed before store release. `npm audit fix --force` would downgrade incompatible framework versions and is unsuitable.
